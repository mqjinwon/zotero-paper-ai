# Paper RAG Implementation Plan (v2)

> **Gate:** Start only after user says 「구현 시작」.  
> **Spec:** `docs/superpowers/specs/2026-08-03-paper-rag-design.md` (v2)

**Goal:** Full-paper RAG for Q&A + figure/equation explain. BM25 zero-key path + optional user-configured embeddings hybrid. No other Zotero plugins. Delete draft `src/rag/*` and rewrite.

**Architecture:** In-process `src/rag/*`; prefs for `ragRetrievalMode` + `embeddingProvider`.

## Phase R1 tasks (ordered)

1. Delete `src/rag/*` draft completely.  
2. Implement extract (full paper) + section parent–child chunk + JSON store.  
3. Implement BM25 retrieve + parent expand + stuff fallback.  
4. Implement embeddings client + hybrid; honor prefs (`none` / `openai` / `openai-compatible`, `auto`/`bm25`/`hybrid`).  
5. `ensureIndex` / `queryPaper` API.  
6. Wire chat + figure-explain + equation-explain; leave translate/drag-explain alone.  
7. Preferences UI + short Korean help text (keys optional).  
8. Unit tests (chunk, bm25, store, mode wiring) + `npm run build`.  

## Non-goals R1

Multi-PDF, GROBID required, other plugins, GraphRAG.

## Deviations
- Hybrid fusion uses 0.6 dense + 0.4 BM25 per design v2 (draft had 0.55/0.45); cite labels use `[§Section p.N]` form.
- RAG index failure in panel is non-fatal (answers without evidence + status warning) so chat still works on extract-poor PDFs.
